## Требования

1. Языки - Английский (как стандарт), Немецкий + Французский (Швейцария), Эстонский, Шведский + Норвежский + Финский + Датский (Скандинавия)
1. Гибридный поиск (dense + sparse) - тк документация техническая
1. Compliance - GDPR (Европа) + необходимость пройти SOC 2
1. Нагрузка - предположим скромную нагрузку, например 1 запрос в минуту, пока что не ставилась задача внедрить кодовый ассистент

### Сравнение LLM-моделей

Требования практически диктуют on-premise решение, однако задание прямо предписывает сравнить их с облачными, поэтому облачные модели тоже включены.

| Модель | Лицензия | On-premise? |Комментарии |
|---|---|---|---|
| Llama | Своя, явно запрещает использование в "Operation of critical infrastructure, transportation technologies, or heavy machinery", heavy machinery - может быть проблемой для аудита с небольшой вероятностью, на территории EU можно использовать только текстовые модели | Да | Лучше для европейских языков из задачи, лицензия специфическая |
| Qwen | Apache 2.0 | Да | Имеет широкую линейку моделей разного размера, недостатки - китайское происхождение и поддержка языков |
| Gemma | Своя, открытая | Да | Небольшие модели, нацеленные на использование в скромной инфраструктуре |
| OpenAI GPT | Проприетарная | Нет | Обгоняет self-hosted модели, но не подходит по требованиям безопасности |
| Mistral | Разные варианты | Разные варианты | Рассмотрел эту модель, тк пожалуй только у неё есть облачное API, с которым вероятно пройти аудит по условию задачи. Однако оказалось, что для скандинавских языков модель (и облачная и локальная) существенно проигрывает Qwen |

Выбор таким образом пал на **локально развертываемый Qwen**, предлагаемая **экономичная стартовая** инфраструктура для второй по размеру модели семейства Qwen-3.8-27B (квантизация FP4, memory footprint примерно 20Gb, см. также [qwen-2-5-72b-self-hosted-deployment](https://gigagpu.com/qwen-2-5-72b-self-hosted-deployment/)):

Graphics Card (VRAM): 1x NVIDIA RTX 6000 Ada (48 GB VRAM) GPU  
Processor: AMD Ryzen Threadripper or Intel Xeon  
System Memory: 128 GB ECC DDR5 RAM  
Motherboard: Enterprise Workstation Board  
Power Supply: 1600W Server-grade PSU  
Storage & Case: 2TB NVMe M.2 SSD + High-airflow case  
  
$8,850

**Стоимость владения и использования** - на периоде в 3 года покупка и обслуживание (\~$30 за электричество) такого сервера выиграет и у аренды в ДЦ (\~$350 в месяц) и у Mistral API (для 43200 запросов в месяц, 170 млн in + 20 млн out токенов - \~$475). Однако здесь не учтены возможные расходы на замену комплектующих, а также не учтена скорость развития самих моделей.

**Сравнение качества ответов** - из открытых источников в порядке убывания качества для требуемого набора языков:

* GPT-5.6
* Llama
* Qwen
* Mistral
* Gemma

**Скорость работы** будет зависеть от on-premise инфраструктуры, по скорости работы облачные решения минимум не уступят on-premise (для вменяемых по стоимости решений). Конфигурация выше даст 30-50 токенов в секунду, а API - 80-120+. Для нашей нагрузки в 1 запрос в минуту - не критично.

**Удобство и простота развёртывания** - примерно одинаковое для локальных и API моделей (для локальных чуть сложнее), для локальных решения типа vllm и llama.cpp настраиваются достаточно просто.

### Сравнение моделей эмбеддингов

**Качество поиска**

В расчёт принимался фактор используемых языков, в качестве источника принятия решения использовались бенчмарки MTEB:

* [Scandinavian](https://mteb-leaderboard.hf.space/benchmark/MTEB(Scandinavian%2C%20v1)?st=1&openreq=weights%2Clicense)
* [Deutsch](https://mteb-leaderboard.hf.space/benchmark/MTEB(deu%2C%20v1))
* [French](https://mteb-leaderboard.hf.space/benchmark/MTEB(fra%2C%20v1))
* [Europe](https://mteb-leaderboard.hf.space/benchmark/MTEB(Europe%2C%20v1))
* [English](https://mteb-leaderboard.hf.space/benchmark/MTEB(eng%2C%20v2)?s.summary=tt%3ARetrieval&d.summary=desc)

По результатам retrieval бенчмарков рассматривались семейства открытых (Apache 2.0) локальных моделей Qwen3 и F2LLM-v2, также сравнивались с OpenAI / text-embedding-3-large т.к. это требуется по условию задачи (вообще такое нельзя использовать, см. секцию про выбор LLM).

Qwen лучше себя показывает для английских текстов, а F2LLM-v2 - для европейских и скандинавских языков. Модель OpenAI уступает обеим локальным моделям, как это ни странно (хотя для части бенчмарков нет данных).

Выбор пал на **локальную F2LLM-v2-14B** , но держим в уме потенциальную замену на Qwen, если на английских текстах F2LLM покажет себя плохо. 

Также если по каким-то причинам нам понадобится нулевая терпимость к моделям китайского происхождения, то лучший кандидат - nomic-ai/nomic-embed-text-v1.5 .

**Скорость создания индекса** - не так критична для объёма прироста в 400 страниц в месяц, выглядит так, что 13 страниц в день можно проиндексировать даже на скромной локальной машине с CPU.

**Стоимость владения** - см. раздел LLM, возможно запустить на той же машине с квантизацией 4 бита (8 Gb VRAM).

### Сравнение векторных баз

**Сложность внедрения и поддержки**

FAISS и ChromaDB - embedded базы, их просто внедрить для экспериментов, но для многопользовательской среды с параллельным выполнением придётся писать свой код, который придётся потом поддерживать.

Qdrant - Production-ready решение, очень просто развернуть в Docker.

**Cкорость поиска и индексации**

Для наших целей по скорости подойдёт любая БД, см. например: [Fastest Vector Database](https://ranksquire.com/2026/02/24/fastest-vector-database-2026/#9-the-performance-caveat-speed-vs-cost)

**Стоимость владения (учёт инфраструктуры)**

Для начального уровня можно запустить Qdrant на той же машине, что и LLM + Embeddings (см. выше), Qdrant не будет сражаться за VRAM.
